# 项目设计报告

## 一、系统背景

在互联网产品运营中，用户流失直接影响产品收入、用户活跃度和长期竞争力。企业通常通过分析用户行为数据、评论反馈和服务使用情况，提前识别存在流失风险的用户，并采取定向优惠、专属服务、回访关怀等方式进行挽留。

本项目设计并实现"企业客户流失预警与挽留分析系统"，通过**实时爬取公开真实用户数据**，结合**NLP文本挖掘、聚类分群、多模型集成、超参优化、SHAP可解释性分析**等深度挖掘技术，识别影响用户流失的关键因素，输出预测结果与业务建议。

## 二、系统总体设计

系统由七个模块组成：

1. **实时数据爬取模块** - 从 Steam 公开 API 爬取真实用户评论数据
2. **数据预处理模块** - 缺失值填充、特征衍生、分类变量编码
3. **NLP文本挖掘模块** - 基于词典的情感分析 + jieba分词 + 词云可视化
4. **数据可视化模块** - 流失分布、行为特征、情感趋势等图表
5. **客户聚类分群模块** - K-Means聚类 + PCA降维可视化 + 肘部法则
6. **多模型训练与评估模块** - 6个模型 + GridSearchCV + Stacking集成
7. **模型可解释性与稳定性评估模块** - SHAP分析 + 交叉验证 + 学习曲线

## 三、系统各模块功能

### 1. 实时数据爬取模块

系统通过 Steam 公开评论 API 实时爬取用户评论数据，包括：
- 用户游戏时长、拥有游戏数、历史评论数
- 评论内容、评分（好评/差评）、获赞数
- 评论时间、是否免费获取、是否抢先体验

爬虫具备：随机UA、请求限速、自动重试、本地缓存、备用数据生成等机制。

### 2. 数据预处理模块

- 数值型字段：缺失值填充、负值裁剪
- 衍生特征：游戏时长（小时）、评论长度、参与度分数、流失信号分
- 目标变量：基于差评、低活跃度、短评论等多维度信号综合判定

### 3. NLP文本挖掘模块

- 基于情感词典（正面/负面词库 + 否定词 + 程度副词）的情感评分
- jieba 中文分词 + 停用词过滤
- 词云可视化（全量/流失/留存三类）
- 高频关键词对比分析
- 情感倾向与流失率的交叉分析

### 4. 数据可视化模块

- 客户流失总体分布（饼图）
- 不同使用时长的流失率（柱状图）
- 不同产品的流失率（柱状图）
- 游戏时长与参与度关系（散点图）
- 情感分数变化趋势（折线图）

### 5. 客户聚类分群模块

- K-Means 聚类（K=3~8 自动选择最优K值）
- 评估指标：轮廓系数、Davies-Bouldin指数、Calinski-Harabasz指数
- PCA 降维可视化
- 肘部法则确定最优簇数
- 各分群统计特征画像

### 6. 多模型训练与评估模块

训练 6 个模型并进行对比：
- 逻辑回归（含标准化 + 类别平衡）
- 决策树（含剪枝参数）
- 随机森林（300棵树）
- 梯度提升树（GBDT）
- XGBoost
- LightGBM

每个模型通过 GridSearchCV 进行超参数优化，最终构建 Stacking 集成模型。

### 7. 模型可解释性与稳定性评估

- **SHAP分析**：KernelExplainer 计算每个特征对预测的贡献
- **5折交叉验证**：评估 F1 和 AUC 的均值与标准差
- **学习曲线**：判断模型是否过拟合/欠拟合
- **混淆矩阵**：计数矩阵 + 行归一化矩阵

## 五、系统功能测试说明

1. 验证爬虫是否能正常获取数据，检查备用数据生成机制
2. 检查 NLP 情感分析的准确性，对比人工标注结果
3. 验证聚类分群的合理性，观察各分群特征差异
4. 比较 6 个模型的评估指标，验证 Stacking 集成是否提升效果
5. 检查 SHAP 分析结果是否与业务直觉一致
6. 验证交叉验证结果的稳定性

## 六、课程总结参考

通过本项目的设计与实现，我掌握了：
- 实时数据爬取与 API 调用技术
- NLP 文本情感分析与中文分词
- 无监督学习（K-Means 聚类）的客户分群方法
- 多种集成学习模型的训练与超参优化
- Stacking 模型集成策略
- SHAP 模型可解释性分析
- 交叉验证与学习曲线的模型评估方法
- Streamlit 交互式数据产品开发

项目创新点在于将传统的数据分析升级为深度挖掘模式，从单一的分类预测扩展为"爬取→NLP→聚类→多模型→可解释性→策略输出"的完整智能分析链路。
